# The greppable invariants of this tree

Generated from the table in `crates/indexwerk-checks/src/terms.rs`. A test asserts
that this file is exactly what that table renders, so an invariant added to the
check and not to this file reds the gate, and an entry written here that the check
does not hold reds it too. Do not edit this file by hand.

The mechanism is taken from the merge gate this board takes as its quality target,
[Flowfin/jellyfin-plugin-sso](https://github.com/Flowfin/jellyfin-plugin-sso). The
invariants are not, because an invariant worth enforcing is a property of this code
rather than of that one. Issue #41 is where the set was argued.

## What a finding says

A finding names the file, the line, the construct, the invariant it broke and where
that invariant comes from. The source is the point: somebody meeting a red check is
being told why the rule exists, not how to silence it.

## What this cannot do

It is a line scan. It reads text and never a parse tree, so it judges spellings, and
a construct written in a spelling no term names walks through it. Widening the terms
is a change to the check that shows up in a diff, which is the repair.

The performance-number invariant is the crudest of the six and deliberately so. It
reads a digit run followed by an ASCII time unit, and it accepts a command block or
a word saying the figure is somebody else's within ten lines. A figure spelled out
in words is not seen, and a command ten lines away that produced something else is
accepted. A crude check that fires on a real defect is worth more than an exact one
nobody writes.
